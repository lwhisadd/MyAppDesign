# MyAppDesign

技術設計、技術棧選型、Agent 協作與部署方案的討論／決策紀錄庫。

---

## ⚠️ 重要閱讀說明（給 AI Agent 與設計人員）

本 Repository 的根目錄分成兩種類型：

1. **共用／工具目錄**：提供跨討論情境使用的 Agent 規範、交接流程、開發工具與使用說明。
2. **技術討論目錄**：各自代表一個獨立的技術討論集合，彼此之間沒有預設的繼承、依賴或延伸關係。

> **只有技術討論目錄需要遵守「單一目錄＝單一 context」原則。**
>
> 不可把不同技術討論目錄的技術決策自動合併、交叉引用，或視為同一套方案的組成部分。

### 技術討論目錄的閱讀規則

- **單一目錄即為單一完整方案**：同一目錄內的文件共同構成一次完整的技術討論，應整體閱讀，不可任意拆散判斷。
- **禁止跨目錄混合推論**：不同目錄可能採用不同技術棧、不同架構決策，強行合併可能產生矛盾或錯誤結論。
- **禁止自動遷移技術決策**：A 目錄決定使用某技術，不代表 B 目錄也適用。
- **跨目錄比較必須標注來源**：若任務本身需要比較多個方案，可以跨目錄閱讀，但結論必須清楚標明來源目錄，不得混成單一方案。
- **目錄間無預設優先順序**：不同目錄不代表版本迭代，不存在「舊版」與「新版」關係，除非文件本身明確說明。
- **同一目錄內依文件順序判讀**：若存在多份具順序的文件（例如 `討論1.md`、`討論2.md`），應依檔名／編號順序閱讀；後續文件可能修正前面的決策。
- **同目錄衝突以較新的明確決策為準**：若同一討論集合內出現矛盾，優先採用後續文件中明確修正或確認的結論。

## 給 AI Agent 的工作原則

本 Repository 供多輪、多主題的技術設計與 Agent 協作使用。開始工作時請遵守以下原則：

1. **先確認工作範圍**：確認本次任務屬於哪一個技術討論目錄，或是否屬於共用／工具文件。
2. **技術討論維持 Context 邊界**：分析單一方案時，只使用該技術討論目錄內的內容，不自動混入其他討論目錄。
3. **需要比較時明確標示來源**：跨目錄比較是允許的，但必須將不同方案分開描述。
4. **目錄內完整閱讀**：同一討論目錄有多份文件時，應依合理順序完整閱讀，避免只取單一文件下結論。
5. **實際狀態優先**：Repository 的實際檔案、Git 狀態與可重現的驗證結果，優先於 README、交接摘要或對話記憶。
6. **共用規範另外處理**：`Agent共用文件/` 屬於跨任務工作規範，不應被誤認為某個技術方案的一部分。
7. **不確定時標示待確認**：不得把推測或過期資訊寫成已確認事實。

進行較長時間工作、任務交接或上下文整理時，請優先閱讀：

- `Agent共用文件/README.md`
- `Agent共用文件/PROJECT_CONTEXT_HANDOFF.md`

- 不同技術討論目錄可能針對相同問題提出不同解法，這通常是刻意保留的比較方案，不代表內容重複或錯誤。
- 若需要整理跨目錄比較文件，請明確標注每項決策的來源目錄。
- 若 README 與 Repository 實際內容不一致，以實際 Git 內容為準，並同步更新 README。
