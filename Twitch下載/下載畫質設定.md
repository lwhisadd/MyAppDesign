# Twitch 下載畫質設定

> 適用範圍：`Twitch下載/` 獨立專案。  
> 決策狀態：待使用者指定畫質值。  
> 使用者決策：下載畫質必須設定成變數，不得硬編碼。  
> 建立日期：2026-08-09

---

## 1. 決策結論

本專案的 Twitch 下載畫質必須設定成變數。

Agent / Hermes / Worker / runner 不得把畫質選擇硬編碼在 prompt、shell script、systemd unit 或 execution manifest 中。

目前只確認「畫質要變數化」，尚未確認實際下載畫質。因此變數值先標示為 `to_be_configured`。

---

## 2. 任務變數

```yaml
TWITCH_VIDEO_QUALITY_POLICY:
  # 畫質設定狀態。
  # 用途：提醒 Agent 目前只確認要變數化，尚未確認實際畫質值。
  # 行為：若為 to_be_configured，Agent 不得自行推測最高畫質、1080p 或 720p。
  configuration_status: "to_be_configured"

  # 下載畫質模式。
  # 用途：由使用者指定實際畫質策略。
  # 合法方向範例：best、1080p、720p、audio_only、custom_format_selector。
  # 目前狀態：待使用者指定。
  quality_mode: "to_be_configured"

  # yt-dlp format selector。
  # 用途：runner 實際呼叫 yt-dlp 時使用的格式選擇器。
  # 注意：在使用者確認畫質前，Agent 不得自行填入 bestvideo+bestaudio/best 或其他值。
  ytdlp_format_selector: "to_be_configured"

  # 是否允許 Agent 自行選最高畫質。
  # 行為：false 表示必須等使用者指定畫質策略。
  agent_may_assume_best_quality: false

  # 是否允許 Agent 自行降低畫質以節省空間。
  # 行為：false 表示不得因磁碟空間或速度自行改成 720p / 480p。
  agent_may_lower_quality_without_user_confirmation: false

  # 若畫質尚未設定時的處理。
  # 行為：建立任務前應回報需要使用者輸入，而不是自行猜測。
  if_quality_not_configured: "requires_user_input"

  # 任務報告中應記錄的畫質設定狀態。
  # 用途：result.json / download-report.json 應記錄實際使用的 quality_mode 與 ytdlp_format_selector。
  report_required: true
```

---

## 3. Agent 執行規則

Agent 在建立 `execution-manifest.json` 時，必須加入畫質設定欄位。

若畫質尚未設定，manifest 不得偽造預設值，應標示：

```json
{
  "video_quality_configuration_status": "to_be_configured",
  "video_quality_mode": "to_be_configured",
  "requires_user_input": true
}
```

若未來使用者指定畫質，Agent 必須更新本文件，並在 manifest 中寫入實際值。

---

## 4. 禁止行為

除非使用者明確指定，Agent / Hermes / Worker / runner 不得：

1. 自行假設下載最高畫質。
2. 自行假設下載 1080p、720p、480p 或 audio only。
3. 自行把 yt-dlp format selector 寫死在 runner。
4. 因磁碟空間不足自行降低畫質。
5. 因網路速度自行降低畫質。
6. 未更新本文件就更改 execution-manifest.json 中的畫質策略。
