# Twitch 下載畫質設定

> 適用範圍：`Twitch下載/` 獨立專案。  
> 決策狀態：已確認目標畫質與第一層 fallback。  
> 使用者決策：優先下載 1080p；若沒有 1080p，改下載 720p；畫質必須設定成變數，不得硬編碼。  
> 建立日期：2026-08-09
> 最近更新：2026-08-09，設定 1080p 不可用時 fallback 到 720p。

---

## 1. 決策結論

本專案的 Twitch 下載畫質必須設定成變數。

使用者已指定：

1. 目標下載畫質為 **1080p**。
2. 若沒有 1080p，改下載 **720p**。

Agent / Hermes / Worker / runner 不得把畫質選擇硬編碼在 prompt、shell script、systemd unit 或 execution manifest 中。

目前已確認第一層 fallback 為 720p；但若 Twitch 來源同時沒有 1080p 與 720p 時，後續處理方式尚未確認。因此第二層 fallback 行為仍標示為 `to_be_confirmed`。

---

## 2. 任務變數

```yaml
TWITCH_VIDEO_QUALITY_POLICY:
  # 畫質設定狀態。
  # 用途：提醒 Agent 已確認 1080p 與 720p fallback，但尚未確認低於 720p 時的處理。
  configuration_status: "configured_1080p_with_720p_fallback"

  # 主要下載畫質模式。
  # 使用者決策：1080p。
  # 行為：runner 應優先以 1080p 作為目標下載畫質。
  quality_mode: "1080p"

  # 主要目標解析度高度。
  # 用途：讓 runner 與報告用結構化數值表示 1080p。
  target_height: 1080

  # 第一層 fallback 畫質模式。
  # 使用者決策：若沒有 1080p，下載 720p。
  fallback_quality_mode: "720p"

  # 第一層 fallback 解析度高度。
  # 用途：讓 runner 與報告用結構化數值表示 fallback 目標。
  fallback_height: 720

  # yt-dlp format selector。
  # 用途：runner 實際呼叫 yt-dlp 時使用的格式選擇器。
  # 行為：優先選 1080p；若沒有 1080p，改選 720p。
  # 注意：此值是變數，由 Agent / runner 讀取，不得在 runner 程式中另行硬編碼。
  ytdlp_format_selector: "bestvideo[height=1080]+bestaudio/best[height=1080]/bestvideo[height=720]+bestaudio/best[height=720]"

  # 是否允許 Agent 自行選最高畫質。
  # 行為：false 表示不得把 1080p 改成 best / source / highest。
  agent_may_assume_best_quality: false

  # 是否允許 Agent 自行降低畫質以節省空間。
  # 行為：false 表示不得因磁碟空間或速度自行改成 480p 或其他低於 720p 的畫質。
  agent_may_lower_quality_without_user_confirmation: false

  # 若來源沒有 1080p 時的處理。
  # 使用者決策：改下載 720p。
  if_1080p_unavailable: "fallback_to_720p"

  # 若來源同時沒有 1080p 與 720p 時的處理。
  # 狀態：待使用者確認。
  # 下一步需要決定：A. 不下載該影片；B. 允許下載低於 720p 的最佳版本；C. 只通知使用者。
  if_1080p_and_720p_unavailable: "to_be_confirmed"

  # 若第二層 fallback 尚未設定時的處理。
  # 行為：遇到無 1080p 且無 720p 的影片時，應回報需要使用者確認，不得自行下載 480p 或更低畫質。
  if_second_fallback_not_configured: "requires_user_input"

  # 任務報告中應記錄的畫質設定狀態。
  # 用途：result.json / download-report.json 應記錄實際使用的 quality_mode、target_height、fallback_height 與實際下載高度。
  report_required: true
```

---

## 3. Agent 執行規則

Agent 在建立 `execution-manifest.json` 時，必須加入畫質設定欄位。

manifest 應標示：

```json
{
  "video_quality_configuration_status": "configured_1080p_with_720p_fallback",
  "video_quality_mode": "1080p",
  "target_height": 1080,
  "fallback_quality_mode": "720p",
  "fallback_height": 720,
  "quality_fallback_policy": "fallback_to_720p",
  "second_fallback_policy": "to_be_confirmed"
}
```

若未來使用者指定低於 720p 時的處理方式，Agent 必須更新本文件，並在 manifest 中寫入實際值。

---

## 4. 禁止行為

除非使用者明確指定，Agent / Hermes / Worker / runner 不得：

1. 自行把 1080p 改成最高畫質、source 或 best。
2. 自行假設沒有 1080p 時可以下載 720p 以外的畫質。
3. 自行假設沒有 1080p 與 720p 時可以下載 480p 或更低畫質。
4. 自行假設沒有 1080p 與 720p 時應跳過影片。
5. 自行把 yt-dlp format selector 寫死在 runner。
6. 因磁碟空間不足自行降低畫質。
7. 因網路速度自行降低畫質。
8. 未更新本文件就更改 execution-manifest.json 中的畫質策略。

---

## 5. 待確認事項

下一步需要使用者指定：若某支 Twitch 影片同時沒有 1080p 與 720p 可下載版本，Hermes / runner 應如何處理。
