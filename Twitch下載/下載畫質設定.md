# Twitch 下載畫質設定

> 適用範圍：`Twitch下載/` 獨立專案。  
> 決策狀態：已確認目標畫質、第一層 fallback 與無可用畫質時的處理。  
> 使用者決策：優先下載 1080p；若沒有 1080p，改下載 720p；若同時沒有 1080p 與 720p，發送通知訊息，並結束當天作業；畫質必須設定成變數，不得硬編碼。  
> 建立日期：2026-08-09
> 最近更新：2026-08-09，設定 1080p 與 720p 都不可用時通知並結束當天作業。

---

## 1. 決策結論

本專案的 Twitch 下載畫質必須設定成變數。

使用者已指定：

1. 目標下載畫質為 **1080p**。
2. 若沒有 1080p，改下載 **720p**。
3. 若同時沒有 1080p 與 720p，**發送通知訊息，並結束當天作業**。

Agent / Hermes / Worker / runner 不得把畫質選擇硬編碼在 prompt、shell script、systemd unit 或 execution manifest 中。

若影片沒有 1080p 與 720p 可下載版本，Hermes / runner 不得自行改下載 480p 或更低畫質，也不得自行嘗試其他非使用者授權的畫質策略。

---

## 2. 任務變數

```yaml
TWITCH_VIDEO_QUALITY_POLICY:
  # 畫質設定狀態。
  # 用途：提醒 Agent 已確認 1080p、720p fallback，以及沒有 1080p/720p 時的處理。
  configuration_status: "configured_1080p_with_720p_fallback_and_notify_end_day_on_unavailable"

  # 主要下載畫質模式。
  # 使用者決策：1080p。
  # 行為：runner 應優先以 1080p 作為目標下載畫質。
  quality_mode: "1080p"

  # 主要目標解析度高度。
  # 用途：讓 runner 與報告用結構化數值表示 1080p。
  target_height: 1080

  # 第一層 fallback 畫質模式。
  # 使用者決策：若沒有 1080p，下載 720p。
  fallback_quality_mode: "720p"

  # 第一層 fallback 解析度高度。
  # 用途：讓 runner 與報告用結構化數值表示 fallback 目標。
  fallback_height: 720

  # yt-dlp format selector。
  # 用途：runner 實際呼叫 yt-dlp 時使用的格式選擇器。
  # 行為：優先選 1080p；若沒有 1080p，改選 720p。
  # 注意：此值是變數，由 Agent / runner 讀取，不得在 runner 程式中另行硬編碼。
  ytdlp_format_selector: "bestvideo[height=1080]+bestaudio/best[height=1080]/bestvideo[height=720]+bestaudio/best[height=720]"

  # 是否允許 Agent 自行選最高畫質。
  # 行為：false 表示不得把 1080p 改成 best / source / highest。
  agent_may_assume_best_quality: false

  # 是否允許 Agent 自行降低畫質以節省空間。
  # 行為：false 表示不得因磁碟空間或速度自行改成 480p 或其他低於 720p 的畫質。
  agent_may_lower_quality_without_user_confirmation: false

  # 若來源沒有 1080p 時的處理。
  # 使用者決策：改下載 720p。
  if_1080p_unavailable: "fallback_to_720p"

  # 若來源同時沒有 1080p 與 720p 時的處理。
  # 使用者決策：發送通知訊息，並結束當天作業。
  # 行為：不得下載 480p 或更低畫質；不得繼續嘗試其他畫質；當天作業結束。
  if_1080p_and_720p_unavailable: "notify_user_and_end_daily_job"

  # 通知管道。
  # 用途：沿用本專案既有通知設定，由 Hermes runtime 透過既有 Discord 綁定發送。
  # 注意：不得在本文件保存 Discord webhook、bot token 或 channel secret。
  quality_unavailable_notify_channel: "discord_via_hermes_existing_binding"

  # 無可用畫質時的任務狀態。
  # 用途：寫入 result.json、download-report.json 與 Hermes DB。
  # 行為：表示當天作業已因畫質不符合政策而結束，不是一般下載失敗重試。
  task_status_when_quality_unavailable: "ended_for_day_quality_unavailable"

  # 是否允許低於 720p 的第二層 fallback。
  # 使用者決策：不允許；同時沒有 1080p 與 720p 時通知並結束當天作業。
  allow_below_720p_fallback: false

  # 任務報告中應記錄的畫質設定狀態。
  # 用途：result.json / download-report.json 應記錄實際使用的 quality_mode、target_height、fallback_height、實際下載高度與是否因無可用畫質結束當天作業。
  report_required: true
```

## 3. Agent 執行規則

Agent 在建立 `execution-manifest.json` 時，必須加入畫質設定欄位。

manifest 應標示：

```json
{
  "video_quality_configuration_status": "configured_1080p_with_720p_fallback_and_notify_end_day_on_unavailable",
  "video_quality_mode": "1080p",
  "target_height": 1080,
  "fallback_quality_mode": "720p",
  "fallback_height": 720,
  "quality_fallback_policy": "fallback_to_720p",
  "if_1080p_and_720p_unavailable": "notify_user_and_end_daily_job",
  "allow_below_720p_fallback": false,
  "quality_unavailable_notify_channel": "discord_via_hermes_existing_binding"
}
```

若 runner 發現某支影片同時沒有 1080p 與 720p 可下載版本，必須：

1. 停止當天下載作業。
2. 透過 Hermes 既有 Discord 綁定發送通知訊息。
3. 不得下載 480p 或更低畫質。
4. 不得繼續處理當天剩餘下載項目。
5. 將任務狀態寫為 `ended_for_day_quality_unavailable`。
6. 在 `result.json` 與 `download-report.json` 中記錄觸發原因、影片來源、實際可用畫質、目標畫質、fallback 畫質與通知狀態。

---

## 4. 通知內容規則

當同時沒有 1080p 與 720p 時，Hermes 應發送通知。

通知內容至少包含：

```json
{
  "event": "twitch_quality_unavailable",
  "worker_id": "PI16G001",
  "task_id": "<TASK_ID>",
  "source_url": "<TWITCH_SOURCE_URL>",
  "required_quality": "1080p",
  "fallback_quality": "720p",
  "action": "ended_daily_job"
}
```

通知文字建議模板：

```text
Twitch 下載任務 {task_id} 已結束當天作業：來源 {source_url} 同時沒有 1080p 與 720p 可下載版本。依照畫質策略，不下載 480p 或更低畫質。
```

---

## 5. 禁止行為

除非使用者未來明確修改本策略，Agent / Hermes / Worker / runner 不得：

1. 自行把 1080p 改成最高畫質、source 或 best。
2. 自行假設沒有 1080p 時可以下載 720p 以外的畫質。
3. 自行假設沒有 1080p 與 720p 時可以下載 480p 或更低畫質。
4. 自行忽略通知並繼續當天下載作業。
5. 自行把 yt-dlp format selector 寫死在 runner。
6. 因磁碟空間不足自行降低畫質。
7. 因網路速度自行降低畫質。
8. 未更新本文件就更改 execution-manifest.json 中的畫質策略。
