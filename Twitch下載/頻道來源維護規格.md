# Twitch 頻道來源維護規格

> 適用範圍：`Twitch下載/` 獨立專案。  
> 決策狀態：已建立格式與維護規則；不填入實際頻道。  
> 目的：定義 `TWITCH_CHANNEL_SOURCES` 的資料格式、維護方式、驗證規則、Agent 禁止行為與空清單處理。  
> 建立日期：2026-08-09

---

## 1. 結論

本文件只規定 Twitch 下載來源的格式與維護規則，不指定任何實際 Twitch 頻道。

實際下載來源的唯一真相來源仍是：

```text
Twitch下載/PI16G001_Hermes_Twitch歸檔Worker設定.md
```

其中的變數：

```yaml
TWITCH_CHANNEL_SOURCES
```

若 `TWITCH_CHANNEL_SOURCES` 為空，Hermes / Agent / Worker / runner 不得猜測、搜尋或自行加入任何頻道，必須回報：

```text
requires_user_input_channel_sources_empty
```

---

## 2. 來源清單資料結構

`TWITCH_CHANNEL_SOURCES` 必須是 YAML array。

每一筆來源必須使用以下格式：

```yaml
TWITCH_CHANNEL_SOURCES:
  - source_id: "example_channel_vods"
    channel_name: "example_channel"
    source_url: "https://www.twitch.tv/example_channel/videos"
    source_type: "channel_videos"
    enabled: true
    authorization_status: "user_confirmed"
    note: "使用者指定的 Twitch 頻道影片來源"
```

---

## 3. 欄位定義

### 3.1 `source_id`

```yaml
source_id: "example_channel_vods"
```

用途：

1. 作為來源的穩定識別碼。
2. 寫入 `execution-manifest.json`、`download-report.json` 與 log。
3. 避免只用 `channel_name` 判斷來源，因為同一頻道未來可能有不同來源類型。

規則：

1. 必填。
2. 必須在清單內唯一。
3. 建議使用小寫英數、底線或連字號。
4. 不得包含空白、token、cookie 或私密資訊。

---

### 3.2 `channel_name`

```yaml
channel_name: "example_channel"
```

用途：

1. Twitch 頻道名稱。
2. 供資料夾命名、報表分類與人工識別使用。

規則：

1. 必填。
2. 不得放 URL。
3. 不得放 display name 以外的私密備註。
4. 若頻道名稱與 URL 不一致，Agent 必須標示 `blocked_channel_name_url_mismatch`，不得自行修正。

---

### 3.3 `source_url`

```yaml
source_url: "https://www.twitch.tv/example_channel/videos"
```

用途：

1. runner 交給 yt-dlp 的來源 URL。
2. 可代表頻道影片頁或特定影片 URL。

規則：

1. 必填。
2. 必須是 Twitch URL。
3. 不得包含 OAuth token、cookie、query 中的私密參數或任何 credential。
4. 若 URL 不是 Twitch 網域，Agent 必須回報 `blocked_invalid_source_url_domain`。
5. 若 URL 格式無法判斷，Agent 必須回報 `requires_user_input_invalid_source_url`。

---

### 3.4 `source_type`

```yaml
source_type: "channel_videos"
```

用途：

1. 告訴 Hermes / runner 這個來源的語意。
2. 避免未來 highlights、clips、single video 混用同一解析流程。

允許值：

```yaml
allowed_source_types:
  - "channel_videos"
  - "single_video"
```

目前不啟用：

```yaml
not_enabled_source_types:
  - "highlights"
  - "clips"
  - "live_recording"
```

規則：

1. 目前 MVP 只允許 `channel_videos` 與 `single_video`。
2. 若要加入 `highlights`、`clips` 或 `live_recording`，必須先更新本文件與主設定檔。
3. Agent 不得因 Twitch URL 看起來像 clips 或 live，就自行啟用非允許類型。

---

### 3.5 `enabled`

```yaml
enabled: true
```

用途：

1. 控制該來源是否參與每日下載。
2. 暫停來源時保留設定與歷史脈絡。

規則：

1. 必填。
2. 只能是 boolean。
3. `false` 表示保留來源但不下載。
4. Agent 不得自動把 `false` 改成 `true`。

---

### 3.6 `authorization_status`

```yaml
authorization_status: "user_confirmed"
```

用途：

1. 記錄此來源是否由使用者明確指定。
2. 避免 Agent 自行加入未授權來源。

允許值：

```yaml
allowed_authorization_status:
  - "user_confirmed"
  - "pending_user_confirmation"
```

規則：

1. 實際下載前必須是 `user_confirmed`。
2. 若為 `pending_user_confirmation`，Hermes 不得下載該來源。
3. Agent 不得自行把 `pending_user_confirmation` 改成 `user_confirmed`。

---

### 3.7 `note`

```yaml
note: "使用者指定的 Twitch 頻道影片來源"
```

用途：

1. 保存人工可讀備註。
2. 說明來源用途、維護原因或暫停原因。

規則：

1. 可留空字串，但欄位建議保留。
2. 不得保存 secret、token、cookie、密碼、私人帳號資訊或 Discord webhook。
3. 若 note 中疑似包含 secret，Agent 必須停止並回報 `blocked_secret_detected_in_channel_source_note`。

---

## 4. 空清單規則

目前允許 `TWITCH_CHANNEL_SOURCES` 保持空清單：

```yaml
TWITCH_CHANNEL_SOURCES: []
```

空清單代表：

1. 尚未指定任何 Twitch 下載來源。
2. Hermes 可以完成 bootstrap、preflight、runner 產生與 dry-run。
3. Hermes 不得建立實際下載任務。
4. runner 不得呼叫 yt-dlp 下載。
5. 任務狀態應回報 `requires_user_input_channel_sources_empty`。

空清單不是錯誤，但會阻擋正式下載。

---

## 5. 維護方式

### 5.1 新增來源

新增來源時，必須修改：

```text
Twitch下載/PI16G001_Hermes_Twitch歸檔Worker設定.md
```

只修改 `TWITCH_CHANNEL_SOURCES` 區塊，不得把來源寫入 runner、prompt、systemd unit 或 execution manifest template。

新增來源前，Agent 必須檢查：

1. `source_id` 是否唯一。
2. `channel_name` 是否存在。
3. `source_url` 是否為 Twitch URL。
4. `source_type` 是否為允許值。
5. `enabled` 是否為 boolean。
6. `authorization_status` 是否為 `user_confirmed` 或 `pending_user_confirmation`。
7. 是否含有 secret 或 credential。

---

### 5.2 停用來源

若要暫停下載某來源，應改成：

```yaml
enabled: false
```

不得直接刪除來源，除非使用者明確要求刪除。

停用後：

1. Hermes 不得將該來源放入當次 manifest。
2. runner 不得下載該來源。
3. report 應記錄該來源被 skipped，原因為 `source_disabled`。

---

### 5.3 刪除來源

刪除來源必須由使用者明確指示。

Agent 刪除來源前，必須在回覆中明確列出：

1. 要刪除的 `source_id`。
2. `channel_name`。
3. `source_url`。
4. 刪除後是否仍保留既有已下載影片。

若使用者沒有明確刪除指示，Agent 應使用 `enabled: false`。

---

### 5.4 修改來源 URL

修改 `source_url` 時，Agent 必須視為高風險變更。

必須：

1. 保留同一 `source_id`，除非使用者要求建立新來源。
2. 在 note 中記錄修改原因。
3. 不得因 URL redirect 或搜尋結果自行替換 URL。
4. 若 `channel_name` 與新 URL 不一致，必須停止並回報。

---

## 6. manifest 轉換規則

Hermes 建立 `execution-manifest.json` 時，只能納入：

```yaml
enabled: true
authorization_status: "user_confirmed"
source_type: "channel_videos" 或 "single_video"
```

manifest 中每一筆來源至少包含：

```json
{
  "source_id": "example_channel_vods",
  "channel_name": "example_channel",
  "source_url": "https://www.twitch.tv/example_channel/videos",
  "source_type": "channel_videos"
}
```

不得把 `note` 中的敏感內容寫入 manifest。

---

## 7. report 規則

`download-report.json` 必須記錄來源處理狀態。

最低格式：

```json
{
  "sources_total": 0,
  "sources_enabled": 0,
  "sources_disabled": 0,
  "sources_pending_user_confirmation": 0,
  "sources_downloaded": [],
  "sources_skipped": [],
  "sources_blocked": []
}
```

每個 skipped source 必須包含原因：

```json
{
  "source_id": "example_channel_vods",
  "reason": "source_disabled"
}
```

---

## 8. Agent 禁止行為

Agent / Hermes / Worker / runner 不得：

1. 自行搜尋 Twitch 頻道並加入來源。
2. 從對話推測使用者想下載的頻道。
3. 從瀏覽紀錄、熱門頻道、推薦清單或其他專案文件推測來源。
4. 把 Twitch 來源硬編碼到 runner、prompt、systemd unit 或 manifest template。
5. 把 `enabled: false` 自行改成 `true`。
6. 把 `pending_user_confirmation` 自行改成 `user_confirmed`。
7. 下載未列入 `TWITCH_CHANNEL_SOURCES` 的來源。
8. 下載含有 token、cookie 或 credential 的 URL。
9. 將來源清單與其他根目錄的設定混用。

---

## 9. 驗證結果代碼

Hermes 驗證來源清單時，應使用以下狀態碼：

```yaml
CHANNEL_SOURCE_VALIDATION_STATUS:
  valid: "valid"
  empty: "requires_user_input_channel_sources_empty"
  invalid_domain: "blocked_invalid_source_url_domain"
  invalid_url: "requires_user_input_invalid_source_url"
  duplicate_source_id: "blocked_duplicate_source_id"
  source_disabled: "skipped_source_disabled"
  pending_confirmation: "skipped_pending_user_confirmation"
  secret_detected: "blocked_secret_detected_in_channel_source"
  type_not_allowed: "blocked_source_type_not_allowed"
  channel_name_url_mismatch: "blocked_channel_name_url_mismatch"
```

---

## 10. 已確認事項

- 本文件只定義格式與維護規則。
- 本文件不填入任何實際 Twitch 頻道。
- 實際來源清單仍以主設定檔 `TWITCH_CHANNEL_SOURCES` 為唯一真相來源。
- 空清單允許存在，但會阻擋正式下載。
- Agent 不得猜測、搜尋或自行新增來源。
