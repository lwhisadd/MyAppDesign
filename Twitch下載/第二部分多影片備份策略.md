# 第二部分：多影片備份策略

> 適用範圍：`Twitch下載/` 獨立專案。  
> 功能階段：第二部分 YouTube 頻道備份。  
> 決策狀態：已確認。  
> 建立日期：2026-08-09  
> 最近更新：2026-08-09，確認部分影片上傳失敗時仍可繼續後續 Twitch 下載。  
> 建立時區：Asia/Taipei

---

## 1. 使用者決策

使用者已確認：

```text
A. 如果最近一次任務產生多支影片，全部都要備份到指定 YouTube 頻道。
B. 如果多支影片中有一支上傳 YouTube 失敗，不停止後續 Twitch 下載；成功的照算，失敗的通知，但仍繼續 Twitch 下載。
```

---

## 2. 決策結論

第二部分 YouTube 備份的影片選取規則如下：

```yaml
PHASE_2_MULTI_VIDEO_BACKUP_POLICY:
  youtube_backup_selection_mode: "latest_task_generated_videos"
  if_latest_task_generates_multiple_videos: "upload_all_eligible_videos"
  if_some_videos_upload_success_and_some_fail: "continue_twitch_download_after_notification"
  allow_upload_first_video_only: false
  allow_upload_primary_video_only: false
  allow_manual_selection_without_policy_update: false
  block_twitch_download_on_partial_upload_failure: false
```

也就是：

1. 第二部分只處理最近一次任務產生的影片。
2. 如果最近一次任務產生多支影片，Hermes 必須嘗試備份全部符合條件的影片。
3. Hermes 不得只備份第一支。
4. Hermes 不得只備份所謂主要影片。
5. Hermes 不得自行挑選部分影片。
6. 如果部分影片成功、部分影片失敗，成功的照算，失敗的必須通知並寫入 report。
7. 部分影片上傳失敗不阻擋後續 Twitch 下載。
8. 若未來要改成只備份部分影片，必須先更新本文件。

---

## 3. 合格影片定義

Hermes 只需要備份符合以下條件的影片：

```yaml
ELIGIBLE_LATEST_TASK_VIDEO:
  generated_by_latest_task: true
  local_file_exists: true
  local_file_is_video: true
  file_extension_allowed: true
  file_size_greater_than_zero: true
  file_not_still_being_written: true
  not_already_uploaded_to_youtube: true
```

不符合條件的影片可以略過，但必須寫入 report，並記錄 skipped reason。

---

## 4. 多影片處理流程

當最近一次任務產生多支影片時，Hermes 必須：

```text
讀取最近一次任務產物
  ↓
列出所有最近一次任務產生的影片
  ↓
逐一驗證影片是否符合 YouTube 備份條件
  ↓
排除已上傳或不合格影片
  ↓
將全部合格影片加入 youtube-backup-manifest.json
  ↓
逐一上傳到指定 YouTube 頻道
  ↓
每支影片都記錄 youtube video id 或失敗原因
  ↓
更新 youtube-upload-archive.jsonl
  ↓
產生 youtube-backup-result.json 與 youtube-backup-report.json
  ↓
若有失敗影片，通知使用者但仍允許後續 Twitch 下載
```

---

## 5. 部分成功處理

若多支影片中有部分上傳成功、部分上傳失敗，Hermes 必須：

1. 保留已成功上傳影片的 YouTube video id。
2. 將失敗影片寫入 `youtube-failed-items.json`。
3. 不得刪除本機影片。
4. 不得重複上傳已成功影片。
5. 透過 Hermes 既有 Discord 綁定通知使用者。
6. 允許後續 Twitch 下載繼續。
7. 回報：

```text
succeeded_with_youtube_upload_failures
```

此狀態代表 YouTube 備份有部分失敗，但不阻擋後續 Twitch 下載。

---

## 6. 任務結果統計欄位

`youtube-backup-result.json` 必須包含：

```json
{
  "youtube_backup_selection_mode": "latest_task_generated_videos",
  "if_latest_task_generates_multiple_videos": "upload_all_eligible_videos",
  "if_some_videos_upload_success_and_some_fail": "continue_twitch_download_after_notification",
  "latest_task_videos_total": 0,
  "eligible_videos_total": 0,
  "videos_uploaded": 0,
  "videos_skipped": 0,
  "videos_failed": 0,
  "all_eligible_videos_uploaded": false,
  "failed_uploads_notified": true,
  "twitch_download_allowed_after_backup": true
}
```

---

## 7. 仍然會阻擋後續 Twitch 下載的情況

以下屬於 phase-level blocker，不是單支或部分影片上傳失敗：

1. YouTube OAuth runtime 不可用。
2. YouTube 目標頻道未設定。
3. 找不到最近一次任務產物。
4. 無法讀取最近一次任務產物。
5. youtube upload archive 完全無法寫入。
6. Hermes 無法判斷哪些影片成功、哪些失敗。
7. 偵測到 token、cookie、password 或其他 secret 被寫入 manifest、report、log 或通知。

遇到以上情況，Hermes 必須停止後續 Twitch 下載並通知使用者。

---

## 8. 禁止行為

Hermes / Agent / Worker / runner 不得：

1. 在最近一次任務產生多支影片時只備份第一支。
2. 在最近一次任務產生多支影片時只備份主要影片。
3. 自行選擇部分影片備份。
4. 因為單一影片或部分影片上傳失敗就停止後續 Twitch 下載。
5. 因為影片數量多就自動跳過部分影片。
6. 把部分失敗誤報為全部成功。
7. 忽略失敗影片不通知使用者。
8. 未更新本文件就改成手動挑選或單支影片模式。

---

## 9. 已確認事項

- 第二部分輸出目的地是指定 YouTube 頻道。
- 第二部分只處理最近一次任務產生的影片。
- 如果最近一次任務產生多支影片，全部符合條件者都要嘗試備份。
- 若部分成功、部分失敗，成功的照算，失敗的必須通知。
- 部分影片上傳失敗不阻擋後續 Twitch 下載。
- phase-level blocker 仍會阻擋後續 Twitch 下載。
